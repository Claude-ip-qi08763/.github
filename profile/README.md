<p>第一项硬指标是可用率。注意不是连通率，而是连续跑一段时间里成功请求所占的比例。这两个数经常差得很远，因为连通测试只发几个请求，而真实业务是持续跑的。这个数字必须自己压测，服务商给的都是挑过的样本。</p>

<p>第二项是响应时间的分位数。均值好看没有意义，要看百分之九十五的分位落在哪里。批量任务里决定整体耗时的不是平均速度，而是那百分之五的长尾请求，它们会把整批任务的时间拖长好几倍。</p>

<p>第三项是目标地区的实际线路数量。宣称覆盖一百个地区，和某个具体地区有足够线路，是完全不同的两件事。如果目标地区只有几条线，高峰期基本排不上，表现出来就是随机超时，很难查。</p>

<p>第四项是会话保持能力。需要连续操作的业务，会话中途断开比一开始就连不上更麻烦，因为状态已经建立了一半，重来还要处理残留。评估时要专门测：连续跑一小时，看会话有没有被打断。</p>
